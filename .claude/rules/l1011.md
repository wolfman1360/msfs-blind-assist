# iniBuilds L-1011 TriStar rules

Loaded when Claude reads matching code. Background: docs/l1011.md. Full text of each rule: docs/invariants/l1011.md.

- [L1011-1] A map-driven TriStar row or breaker write REPLAYS the cockpit's own click (its L:var writes, H: and K: events, in order) as ONE `ExecuteCalculatorCodeUnique` string (`L1011WritePlan`), never `SetLVar` or a bare L:var write. `L1011Levers` is the one exception; every write is refused aloud when `CalcWriteCanLand` is false. (more: see full) Full: docs/invariants/l1011.md#l1011-1
- [L1011-2] `l1011_control_map.json` is GENERATED by `tools/l1011-gen` from the aircraft's compiled cockpit behaviour and tooltips: never hand-edit it; regenerate after an iniBuilds update and review with `diff_maps.py`. iniBuilds' files and any decoded copy stay out of the repo. Full: docs/invariants/l1011.md#l1011-2
- [L1011-3] `L1011PanelLayout` and its `L1011LayoutRows.*.cs` files are the ONLY source of panel order (the manual's preflight flows), discriminator first in every name, a guard directly before its switch. `SpokenWord` sentence-cases position words but keeps single letters, words with a digit and its abbreviations in capitals. Full: docs/invariants/l1011.md#l1011-3
- [L1011-4] A transition carrying a TOGGLE K: event is REFUSED while the current position is unknown, and a just-commanded position is trusted for 2.5 s over the 1 Hz cache (`L1011CommandedState`): a toggle sent the wrong way inverts the switch and the system behind it. Full: docs/invariants/l1011.md#l1011-4
- [L1011-5] The warning-light flush runs in `OnContinuousBatchDelivered`, OUTSIDE MainForm's mute wrap, so it checks `L1011DisabledMonitorVariablesSet` itself; lever call-outs speak inside `ProcessSimVarUpdate`, inside the wrap. A context reset wipes the baselines and `Md11SeedGate` decides the re-seed, never a wall clock. Full: docs/invariants/l1011.md#l1011-5
- [L1011-6] The 981 circuit breakers are NEVER data definitions (the 1,000 budget): the breaker window reads them in one Coherent evaluation of `L1011_ENGINEER_PANEL`. Every row carries its number; the window re-filters only on open, search, the pulled-only filter and Refresh, never after a pull or push. (more: see full) Full: docs/invariants/l1011.md#l1011-6
- [L1011-7] A typed autopilot value is written EXACTLY as the aircraft's knob handler writes it (`L1011Afcs`: heading `K:HEADING_BUG_SET`, altitude `L:ALTITUDE_SETPOINT_0` then `H:AUTOPILOT_CAPTURE_UPDATE`, speed `L:INI_AT_TARGET`, VS `L:INI_VS_PID_SETPOINT_2` then its H: event, courses `K:VOR1_SET`/`K:VOR2_SET`), inside the knob's clamp. (more: see full) Full: docs/invariants/l1011.md#l1011-7
- [L1011-8] Two autopilot refusals come BEFORE anything is sent, as the aircraft undoes the press silently: a pitch or lateral mode while both flight directors and both engage paddles are KNOWN off (`L1011AfcsModes.NeedFlightDirectorOrAutopilot`), and a vertical speed typed while VS mode is known off. An unknown position never refuses. Full: docs/invariants/l1011.md#l1011-8
- [L1011-9] The autopilot speaks only from the aircraft's own variables (`L1011AfcsModes`: paddles, mode buttons, `ANN_*`, `FLARE_ACTIVE`, `ROLLOUT_ACTIVE`), baseline-first; MSFSBA's own press is silent while the switch sits where it was put, a box or key press speaking via its read-back. Never announce the `AFCS_CPT_*` drums or an unconfirmed lamp. Full: docs/invariants/l1011.md#l1011-9
- [L1011-10] Ctrl+P's lines come from the read-only `coherent-l1011-afcs-agent.js` (`#screen_1..8` in `L1011_AFCS`), formatted by `L1011AfcsWindows`. The reader holds the view's one socket only while the shared window is VISIBLE (it hides on close and is reused): follow `VisibleChanged`, never the form's life. Full: docs/invariants/l1011.md#l1011-10
- [L1011-11] Autoflight windows follow the A300's: row-name labels showing the REPORTED position, never the commanded one; each control in one window (`L1011AutoflightWindows`), pressed through its row's write path; all value boxes, Ctrl+B included, share one slot (`ShowValueBox`); box buttons and toggle keys read back fresh, queued; Ctrl+P is silent. Full: docs/invariants/l1011.md#l1011-11
- [L1011-12] `ANN_VOR_ACTIVE` is the VOR capture ONLY while VOR or back course is on (`L1011AfcsModes.FlagModeOn`): L1011_INS.js sets it whenever a navaid is received with no localizer, ILS or back-course mode on, and never clears it when the signal goes. The status list and `L1011AfcsAnnouncer` use the gated value; never list or speak the raw flag. Full: docs/invariants/l1011.md#l1011-12
- [L1011-13] The INS window reads ONE INS view at a time with the read-only `coherent-l1011-ins-agent.js` (`L1011_INS_1` INS 1 + captain's PMS, `_2` INS 2 + first officer's PMS, `_3` INS 3, PMS inert), only while `L1011InsForm` is visible: the spans, `#dot_5`/`#dot_6`, the page L:var, `gpsPoints`, never `INS_WAYPOINTS`. Full: docs/invariants/l1011.md#l1011-13
- [L1011-14] Every INS and PMS key goes through ONE chain (`IniL1011Definition.PressKeys`), so presses never interleave; typed text holding a character the unit has no key for sends NOTHING; "Enter present position" turns the display selector to POSITION first (no other page starts an entry). Full: docs/invariants/l1011.md#l1011-14
- [L1011-15] "INS n navigating" speaks ONLY when a unit starts navigating by itself (MSU already at NAV; its READY NAV flash is below the lamp gate's settle time); at ALIGN the READY NAV lamp speaks and NAV is the pilot's turn. PMS call-outs follow the mode lights (`L1011PmsPhaseAnnouncer`); only INS 1's ALERT lamp speaks (it feeds the captain's HSI). Full: docs/invariants/l1011.md#l1011-15
- [L1011-16] A typed tablet value in a field with a number pad (load sheet, takeoff, landing elevation) commits ONLY through the tablet's own keyboard: `coherent-l1011-efb-agent.js` clicks the field, sets it, fires `input` and presses `#osk-num .osk-hide-num`; input, change and blur alone leave a value the aircraft never took. Full: docs/invariants/l1011.md#l1011-16
- [L1011-17] A tablet press is `el.click()` ALONE, never a pointer or mouse prelude (it starts the tablet's drag sliders), and the reader itself refuses a click-through or dimmed control (`pointer-events: none`, opacity 0.5 or less), because `click()` ignores pointer-events. Full: docs/invariants/l1011.md#l1011-17
- [L1011-18] A tablet setting's value is its LABEL's `active` class, never its radio's `checked` (they disagree on the live tablet, unlike the PMDG toggles of [PEFB-7]), and a setting changes by a click on that label. Full: docs/invariants/l1011.md#l1011-18
- [L1011-19] The tablet reader answers "unchanged" only when its own output is identical, never from a MutationObserver: about 170 DOM changes a second happen with nothing changing for the pilot (hidden pages, ground buttons rewriting their classes), so a mutation gate never closes. Full: docs/invariants/l1011.md#l1011-19
- [L1011-20] Tablet fixtures (`efb-*.html`) are captured with `efb-capture.js`, never `stamp.js`: it keeps only the page shown and strips field values, inline handlers, the OFP text, the Navigraph code and user name, the airport shortcuts and the METAR answer, so no SimBrief ID, plan, airport or account is committed. Full: docs/invariants/l1011.md#l1011-20
- [L1011-21] An engage paddle going to Command from Off or unknown stops at CWS for `L1011WritePlan.PaddleNotchMs` first: L1011_INS.js turns the pitch and roll loops on only in its CWS routine, so a paddle sent straight to Command shows Command and flies nothing. The notch is MSFSBA's own (`L1011Plan.Via`, `L1011CommandedState.IsOwn`), never spoken. Full: docs/invariants/l1011.md#l1011-21
