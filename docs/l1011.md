# iniBuilds L-1011 TriStar

Aircraft code `INI_L1011`, menu item "iniBuilds L-1011 TriStar". Community package
`inibuilds-aircraft-l1011` (MSFS 2024 only; built and tested against package 1.0.8). Design
document: `docs/superpowers/specs/2026-10-02-l1011-tristar-design.md` (local, not in the repo).

Session 1 (this document) covers the switch panels, readouts, warning-light announcements, the
Ctrl+M monitor manager, the circuit-breaker window and the aircraft's own checklist. The
glareshield autopilot panel, the INS/PMS and the Paper Flight Bag EFB are later sessions.

## How a control is written

The TriStar's cockpit gauges re-read a switch only when the H: events its click code fires
arrive. Writing the switch's L:var alone moves the 3D switch and changes nothing else; so does
`SetLVar`'s data-definition write. So every write of a map-driven panel row or a circuit breaker
REPLAYS THE COCKPIT'S OWN CLICK: the L:var writes, H: events and K: events the control's mouse
code performs for the chosen position, in order, as one calculator-path string
(`L1011WritePlan`), sent with `ExecuteCalculatorCodeUnique` so a repeated press is never
coalesced. A string longer than 900 characters is split at effect boundaries (MobiFlight's
command limit is 1024 bytes).

The deliberate exception is the hand-written rows in `L1011Levers`, whose controls the map does
not cover well. They write what the aircraft itself reads rather than replaying a click: the flap
handle writes `A:FLAPS HANDLE INDEX` (as the aircraft's own EFB does); the gear lever goes down
and up through the stock `K:GEAR_DOWN` and `K:GEAR_UP`, which the HANDLING gauge intercepts, and
to Off by writing `L:LEVER_LANDING_GEAR` 50, which that gauge polls; the speed brake writes
`L:LEVER_SPOILERS`, which the HANDLING gauge copies into the stock handle; the ground-spoiler arm
and the parking brake send `K:SPOILERS_ARM_SET` and `K:PARKING_BRAKE_SET`; the typed altimeters,
frequencies and squawk send the stock set events. Each is still one `ExecuteCalculatorCodeUnique`
string, refused aloud when the calculator path cannot land, and never `SetLVar`.

Input mode adds two keys for the same typed values. Ctrl+B opens the shared `ValueInputForm` and
sets all three altimeters (captain, first officer, standby) from one entry, with the typed
altimeter fields' range and error; the three `K:2:KOHLSMAN_SET` writes go as one string
(`L1011Levers.AllAltimetersRpn`) and the pilot hears "Altimeters 1013, 29.92". No STD or units
button: the altimeters are steam gauges. Ctrl+N opens the shared `NavRadiosForm` and sends NAV 1's
and NAV 2's frequency (`K:NAVn_RADIO_SET_HZ`) and course as one string
(`L1011Levers.NavRadiosRpn`); the course goes through `K:VOR1_SET` / `K:VOR2_SET`, which is what
the course knobs' INSTRUMENTS script sends, and lands in `A:NAV OBS:1/2`. It confirms "NAV 1
110.30, course 45; NAV 2 113.90, course 270". The NAV dialog is pre-filled through
`SimConnectManager.RequestNavRadioInfo`, the fixed one-shot read every aircraft's N readout uses
(no new definition), or 108.00 and course 0 when that does not answer within 2 s. Both keys are
refused aloud ("Altimeters unavailable", "NAV radios unavailable") when the calculator path
cannot land, before the dialog opens and again when a value is set. Both dialogs are tracked
windows, so an aircraft switch closes them.

- Buttons: press, hold, release. The hold is 250 ms when the press fires an event and 2 s when it
  only writes an L:var a gauge polls (test buttons, APU start), so the poll cannot miss it.
- Latches (the electrical CLOSE/TRIP buttons): press only; the aircraft resets them.
- Spring switches (fire bottle discharge): the chosen side, held 1.5 s, then back to centre.
- Knobs (dimmers, temperature): a slider; the value goes into the knob's own set template.
- Encoders (knobs that only turn): an "increase" and a "decrease" button.
- A transition that carries a TOGGLE K: event (fuel cutoff valves and a few others) is refused
  while the current position is unknown, because a toggle sent the wrong way inverts the switch.
  The pilot hears "position unknown, try again in a moment".
- What MSFSBA has just commanded is remembered for 2.5 s (`L1011CommandedState`), so two quick
  picks are not both planned from the 1 Hz cache.
- Every write is refused aloud ("{name} unavailable") when `SimConnectManager.CalcWriteCanLand`
  is false, and the row's value is asked for again so its combo goes back to the position the
  aircraft is in (the levers included). The TriStar registers `MSFSBA_BRIDGE_PROBE`, so a missing
  MobiFlight WASM module is reported by the calc-path probe's spoken warning.
- The gear lever's own gauge refuses "up" on the ground: the write lands and nothing moves. So
  after a gear-lever write the lever is read again once, 1.5 s later (`L1011Levers.GearSettleMs`,
  one batch period plus margin: a judgement, not a measurement), and the combo follows what the
  aircraft did.

## The generated control map

`MSFSBlindAssist/Resources/l1011_control_map.json` is GENERATED by `tools/l1011-gen` from the
aircraft's two compiled cockpit behaviour files and its `en-US.locPak` tooltips, and shipped as
an embedded resource. Never hand-edit it. After an iniBuilds update:

```bash
git show HEAD:MSFSBlindAssist/Resources/l1011_control_map.json > old_l1011_map.json
```

```bash
python tools/l1011-gen/generate_l1011_map.py --package "D:\games\MSFS2024\Community2024\inibuilds-aircraft-l1011"
```

```bash
python tools/l1011-gen/diff_maps.py old_l1011_map.json MSFSBlindAssist/Resources/l1011_control_map.json
```

Then build and run the tests: `L1011PanelLayoutTests` fails if a layout row names a control the
new map lost. The checklist is regenerated the same way with `convert_checklist.py`.

Package 1.0.8 gives 778 controls (407 switches, 187 buttons, 67 knobs, 47 encoders, 22 latches,
4 spring switches, 44 the map cannot replay), 981 circuit breakers and 496 lamp variables.

## Panels

`Aircraft/L1011/L1011PanelLayout.cs` and its four row files are the ONLY source of panel order:
the manual's flows (cockpit safety inspection, flight engineer station preparation, overhead,
main panel, center console). Spoken names put the discriminator first ("Tank 2 left pump 1"),
and a row's position words override iniBuilds' tooltip words only where the aircraft has none,
a wrong one, or two the same. The levers, typed values and the breaker button are hand-written
in `L1011Levers`.

iniBuilds' tooltip words are upper case. `L1011PanelLayout.SpokenWord` puts them in sentence case
("ALTITUDE MODE ON" becomes "Altitude mode on") but keeps a single letter ("Loop A", "System B"),
a word with a digit ("1A", "N1") and the abbreviations pilots say as letters (APU, DC, RA, TA:
"TA/RA", "APU generator", "Standby DC bus") in capitals. That list was taken from the words of
the rows the layout places; add to it when a later session places a row with another one (the
map's unplaced AFCS and INS controls carry CWS and INS).

`SWITCH_APU_AUTOFIRE` (APU auto fire shutdown) stops the APU and closes fuel valves 8 and 9 on
EITHER click, on or off: that is iniBuilds' own click code, replayed faithfully. Moving it with
the APU running shuts the APU down.

Two rows are named against iniBuilds' tooltips: the weather radar's OFF and TEST buttons. Their
tooltips are swapped; the gauge (H:SWITCH_WX_OFF selects the OFF mode, `L:WX_Mode` 2) and the
variable ids agree with each other, so the rows follow them.

## Budget

Switch positions, the announced levers and the warning lights ride the continuous batches (435
batch slots; no individual data definitions); readouts and knobs are on-request (126
definitions); buttons and typed entries are never registered. `IniL1011DefinitionTests` caps the
batch at 900 and on-request definitions at 300, leaving room for the later sessions. A position
variable two rows share rides the batch once.

## Announcements and Ctrl+M

- Positions are consumed silently in `ProcessSimVarUpdate`; the open combo follows them
  (`RefreshControlWhenDefHandled`).
- Warning lights (`L1011Annunciators`) speak through `L1011LampGate`: a silent baseline, a 1.2 s
  settle (a flashing lamp is heard once, in the state it settles in) and silence while either
  annunciator light-test switch is on and for 3 s after. They are spoken from
  `OnContinuousBatchDelivered`, outside MainForm's mute wrap, so the flush checks
  `L1011DisabledMonitorVariablesSet` itself.
- The flap handle, parking brake and ground-spoiler arm speak when something other than MSFSBA
  moves them, from `ProcessSimVarUpdate`, where MainForm's wrap applies the Ctrl+M mute and the
  UI echo (`DefAnnounceMuteSets` lists `INI_L1011`).
- A context reset (disconnect, flight load) wipes every baseline; the MD-11's `Md11SeedGate`
  decides from the batch deliveries when the lamps and levers a load left unchanged are seeded
  from the cache.

## Circuit breakers

981 breakers (numbered 1 to 999; 644 named) are never data definitions. The breaker window reads
them all with one Coherent debugger evaluation in the hidden `L1011_ENGINEER_PANEL` view
(`L1011CircuitBreakers.BulkReadScript`), and pulls or pushes one by replaying its click.

- Every row carries its number: "ENG START PWR, breaker 741: in", and "Breaker 12: in" for the
  ones iniBuilds left unnamed. 68 breakers are titled "INOP" and three titles appear twice (ENG
  START PWR 741 and 921, INS-1 DC 787 and 804, AUDIO CONT F/O & OBS 541 and 927), so without it
  rows read the same; the search matches the number too.
- The list is re-filtered only when the window opens, the search or "Show pulled breakers only"
  changes, or Refresh is pressed. A pull or push, and the confirmation read 1.5 s later, rewrite
  the listed rows in place without adding or removing one (`L1011CircuitBreakers.ItemTexts`), so
  the cursor never moves to another breaker; a breaker pushed in while "pulled only" is ticked
  stays listed until the list is next re-filtered.
- A pull or push before the states have been read is refused: "Breaker states unknown. Press
  Refresh." Nothing is sent, because which way the click goes is unknown.

## Troubleshooting

- Breaker window says "Breaker states unavailable": the Coherent debugger did not answer. An
  orphaned `simlink.exe` from an earlier sim session can hold a second listener on port 19999
  and swallow every connection: `netstat -ano | findstr 19999` shows two LISTENING owners. End
  the orphan.
- A control "does nothing": check the calc-path probe's warning (MobiFlight WASM module), then
  `debug.log` for the RPN sent.
