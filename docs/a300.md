# iniBuilds A300-600

Aircraft code `INI_A300`, menu item "iniBuilds Airbus A300-600". Community package
`inibuilds-aircraft-a300` (MSFS 2024; built and tested against package 1.0.11). The four
variants (passenger and freighter, GE and PW engines) share one cockpit behaviour file, panel
configuration and code module, so one definition serves all four. Design document:
`docs/superpowers/specs/2026-10-03-a300-design.md` (local, not in the repo).

Covered so far: the switch panels, a few readouts, the master warning and caution and lever
announcements, the Ctrl+M monitor manager, the aircraft's own checklist (part 1), both MCDUs
(part 2), and the FCU, autopilot and radios with typed values and hotkeys (part 3). Later parts:
the tablet and the display readers.

## How a control is written

Every map-driven row fires the control's own B: event, `value (>B:AIRLINER_<Name>_Set)`, which is
what the cockpit's mouse code calls, through `ExecuteCalculatorCodeUnique` (`A300WritePlan`).
Measured live at a cold-and-dark gate (2026-10-03):

- TWO-POSITION switches (`toggle`, and `command` where the position lives in a separate variable)
  FLIP whatever value the Set event is given; iniBuilds' own `_ON` and `_OFF` bindings flip too.
  So a write is sent only when the current position is known and differs; an unknown position is
  refused aloud ("position unknown, try again in a moment"), and what MSFSBA has just commanded
  is trusted for 2.5 s over the 1 Hz cache (`A300CommandedState`).
- Selectors and knobs are absolute: Set n is position n. A knob's state variable is the Set value
  times the map's `scale` (0.1 for the cabin pressure limit and the weather radar gain).
- Hold buttons (`hold`: ECAM page keys, test buttons) are pressed with Set 2 and released with Set
  0 after 250 ms, which reached the ECAM page keys every time.
- Spring switches (aileron, rudder and yoke pitch trim, the cabin manual V/S switch) are held at
  the chosen side for 1 s and then returned to rest; the aileron trim moved while held and stopped
  at rest.
- Encoders (knobs that only turn) are an "increase" and a "decrease" button, Set +1 and Set -1.
- The flaps lever, ground spoiler arm and speed brake are hand-written (`A300Levers`) with the
  stock events the A300 takes: `K:FLAPS_SET` with index x 4096 (`A:FLAPS HANDLE INDEX` 0 to 4),
  `K:SPOILERS_ARM_SET` (read back from `L:INI_SPOILERS_ARMED`; the stock armed flag stays 0), and
  `K:SPOILERS_SET` 0 to 16384 (read back from `L:INI_SPOILERS_HANDLE_POSITION`, 0 to 1).
- External power, the gear lever and the parking brake fire their own Set event and are read
  from the stock variables (`A:EXTERNAL POWER ON:1`, `A:GEAR HANDLE POSITION`,
  `A:BRAKE PARKING POSITION`).
- Every write is refused aloud ("{name} unavailable") when `CalcWriteCanLand` is false, and the
  row's value is asked for again so its combo goes back. The A300 registers
  `MSFSBA_BRIDGE_PROBE`, so a missing MobiFlight WASM module is reported by the calc-path probe.
- Guard covers only move the 3D model, so they are not rows. The two cargo smoke agent guards
  are real switches: the agent switch springs back to off while its guard reads 0 (read from the
  aircraft's own click code), so they are rows, worded Closed and Open, placed just before their
  switch.

## The generated control map

`MSFSBlindAssist/Resources/a300_control_map.json` is GENERATED by `tools/a300-gen` from the
aircraft's compiled cockpit behaviour file and its `en-US.locPak` tooltips, and shipped as an
embedded resource. Never hand-edit it. After an iniBuilds update:

```bash
git show HEAD:MSFSBlindAssist/Resources/a300_control_map.json > old_a300_map.json
```

```bash
python tools/a300-gen/generate_a300_map.py --package "<Community folder>\inibuilds-aircraft-a300"
```

```bash
python tools/a300-gen/diff_maps.py old_a300_map.json MSFSBlindAssist/Resources/a300_control_map.json
```

`convert_checklist.py` rebuilds `Checklists/iniBuilds_A300_Checklist.txt` from the aircraft's own
checklist the same way. iniBuilds' files and any decoded copy of them stay out of the repo; the
generator's tests run against small fixtures in the same format.

## Panels

`A300PanelLayout` is the only source of panel order. Sections and panels follow the component
tree iniBuilds grouped the cockpit by (Overhead, Glareshield, Main Panel, Pedestal, Cockpit,
Cargo), in the order the cockpit file lists them, so an update is picked up by regenerating the
map. The pedestal's radio and audio group (iniBuilds' "STD") is split by what each control is:
VHF radios, ADF radios, transponder and TCAS, weather radar, captain's and first officer's audio.
Left out: guard covers, the IDC's copies of the radio panel (the same variables), cosmetic parts,
duplicate buttons that fire the same event, and the main cargo door switch (the 145 and 70 degree
buttons drive the same door).

Names come from `A300PanelLayout.Names.cs` where iniBuilds' titles repeat or are wrong ("BATTERY"
three times, "ALTITUDE KNOB" on the vertical speed knob, "CPT BAROMETER" on the first officer's),
from one rule for the audio panels ("VHF 1 receiver", "VHF 1 volume", "VHF 1 transmit"), and
otherwise from the tooltip title through `SpokenWord`.

## Announcements

Spoken from `ProcessSimVarUpdate`, inside MainForm's mute and echo wrap (`DefAnnounceMuteSets`
lists `INI_A300`): the master warning and master caution as they come ON only (pressing the light
writes 0 to the same variable, so speaking it going out would echo the pilot's own press), and
the flaps lever, ground spoiler arm, gear lever and parking brake when something else moves them.
Every other switch position is consumed silently; its combo follows the cockpit. A context reset
wipes the baselines and `Md11SeedGate` decides when the unchanged ones are seeded from the cache.

## MCDUs

`FMGS::Draw()` publishes each MCDU's character grid to a SimConnect client data area,
`iniAirbusMCDU_1` (captain) and `iniAirbusMCDU_2` (first officer): 14 rows x 24 columns x 3 bytes
(character, colour, small-font flag), 1008 bytes, only while `L:INI_MCDU_OPTION` is 1 (the
tablet's External Hardware → MCDU Export). The option does NOT survive a flight load (it read 0
after one), so the MCDU window writes `1 (>L:INI_MCDU_OPTION)` every time it opens. With the
option off the area keeps its last content; an unpowered MCDU is cleared to spaces.

`A300McduDataManager` follows the MD-11 MCDU manager's lifecycle: one per SimConnect connection
(created or reused in `InitializePMDG`, ended by `Disconnect` and the drop path), a registration
that resumes after its last completed step, and per MCDU an ON_SET + CHANGED subscription PLUS a
one-time snapshot on its own request id (the subscription is handed only later writes).

Characters are read as the aircraft's MCDU fonts (INI_CDUA / INI_CDUB) draw them, decoded from the
glyph outlines (`A300McduText.Glyph`): `!` is an empty entry box (read as `#`), `^` the degree
sign, `a`/`l` a left arrow and `b`/`r` a right arrow (the "more pages" arrow beside a title),
`{`/`}` up and down arrows, `~` a delta; every other lowercase letter is drawn as its capital.

Keys are the cockpit's own L:vars, `INI_MCDU1_<KEY>` / `INI_MCDU2_<KEY>`: 1, held 80 ms, 0, then 80
ms before the next, through ONE queue in the definition (`PressMcduKeys`). Measured live: 40 ms
press and gap typed eight letters without a miss; a press and release in one calculator string
did not register. `SPACE` works though no cockpit button writes it. CLR deletes one character per
press, and a CLR on an EMPTY scratchpad puts "CLR" into it, so the window's clear-all re-reads the
screen after each press and stops the moment it reads empty.

## FCU, autopilot and radios

`A300TypedValues` holds every typed value and how it is written, each measured live
(2026-10-03): the FCU windows are their own L:vars (`INI_Airspeed_Dial`, `INI_HEADING_DIAL`,
`INI_Altitude_Dial`, `INI_vvi_dial`), which moved the autopilot's stock targets; the knobs stop at
100-399 knots, Mach 0.10-0.99, altitude 49,000 and vertical speed ±6,000, and heading wraps.
In Mach mode (`INI_Airspeed_is_mach`) the same speed variable holds the Mach number. A typed
value in the other unit presses SPD/MACH and WAITS before writing: the aircraft applies the
switch a moment later and converts what the variable holds then (a value written in the same
string came out as Mach 0.15). VOR 1, VOR 2 and ILS frequencies are written as their `_MHZ` and
`_KHZ` parts (the combined value and the stock NAV radio are rebuilt from them, so writing either
is undone); VOR courses use `K:VOR1_SET`/`K:VOR2_SET`, the ILS course `L:INI_ils_course`. VHF
standby uses the stock set events, the squawk `K:XPNDR_SET`, the altimeters
`index value (>K:2:KOHLSMAN_SET)` (index first; value first does nothing).

The FCU mode buttons show their own lamps (`A300FcuState`: `INI_MCU_*_LIGHT`, `INI_AT_ON`,
`INI_CWS_on`, `INI_Airspeed_is_mach`), registered on the batch, consumed silently and shown only on
the button label through `TryDescribeControlState`. The flight mode annunciator's words are drawn
by the PFD code from mode numbers (`INI_PITCH_MODE`, `INI_ROLL_MODE`) with many interlocks, so
they wait for the display readers.

## Budget

About 275 switch, lever and light variables ride the continuous batches (no individual
definitions); the 57 knobs and the readouts are on-request; buttons and encoder steps are
write-only. A position variable two rows share rides
the batch once and the second row reads it on request.
