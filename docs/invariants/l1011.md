# iniBuilds L-1011 TriStar — rules in full

Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/l1011.md`, which Claude Code loads when it reads matching code. Background: [l1011.md](../l1011.md).
The text is verbatim from CLAUDE.md on `feature/l1011-panels` as of `0ea00497`, moved here when that branch took the lean CLAUDE.md (#265); a trailing "→ doc" pointer is the original's.

## L1011-1

- Every write of a map-driven TriStar panel row or circuit breaker REPLAYS THE COCKPIT'S OWN CLICK: the L:var writes, H: events and K: events the control's mouse code performs for the chosen position, in order, as ONE `ExecuteCalculatorCodeUnique` string (`L1011WritePlan`). Never `SetLVar` and never a bare L:var write there: the TriStar's gauges re-read a switch only when its H: events fire, so the switch moves and nothing else does. The ONE deliberate exception is the hand-written rows in `L1011Levers`, which write what the aircraft itself reads: the flap handle `A:FLAPS HANDLE INDEX` (as the aircraft's own EFB does), the gear lever the stock `K:GEAR_DOWN`/`K:GEAR_UP` (intercepted by the HANDLING gauge) or `L:LEVER_LANDING_GEAR` 50 for Off, the speed brake `L:LEVER_SPOILERS` (both lever L:vars are polled by that gauge), and stock K: events for the spoiler arm, the parking brake and the typed values — still ONE `ExecuteCalculatorCodeUnique` string each, still never `SetLVar`. Every write, the exception included, is refused aloud ("{name} unavailable") when `CalcWriteCanLand` is false; a refused PANEL ROW or LEVER also asks for its value again so its combo snaps back to the aircraft's position (a breaker row is a list item that is not changed before sending, so it needs no re-read); a gear-lever write that was sent is re-read once after `L1011Levers.GearSettleMs`, because the lever's own gauge refuses "up" on the ground. → [l1011.md](../l1011.md)

## L1011-2

- `MSFSBlindAssist/Resources/l1011_control_map.json` is GENERATED by `tools/l1011-gen` from the aircraft's compiled cockpit behaviour and tooltips — never hand-edit it; after an iniBuilds update regenerate it and review with `diff_maps.py`. iniBuilds' files and any decoded copy of them stay out of the repo. → [l1011.md](../l1011.md)

## L1011-3

- `L1011PanelLayout` (and its four row files) is the ONLY source of panel order — the manual's preflight flows — with the discriminator first in every name and a guard directly before its switch (pinned by `L1011PanelLayoutTests`). Its `SpokenWord` sentence-cases iniBuilds' upper-case position words but keeps single letters ("Loop A"), words with a digit and the letter-spoken abbreviations in its set ("TA/RA", "APU generator") in capitals. → [l1011.md](../l1011.md)

## L1011-4

- A transition carrying a TOGGLE K: event is REFUSED while the current position is unknown, and a just-commanded position is trusted for 2.5 s over the 1 Hz cache (`L1011CommandedState`): a toggle sent the wrong way inverts the switch and the system behind it. → [l1011.md](../l1011.md)

## L1011-5

- The warning-light flush runs in `OnContinuousBatchDelivered`, OUTSIDE MainForm's mute wrap, so it checks `L1011DisabledMonitorVariablesSet` itself; the lever call-outs speak inside `ProcessSimVarUpdate`, where the wrap applies. A context reset wipes the baselines and `Md11SeedGate` decides when the unchanged ones are seeded from the cache — never a wall clock. → [l1011.md](../l1011.md)

## L1011-6

- The 981 circuit breakers are NEVER data definitions (they would break the 1,000 budget): the breaker window reads them with one Coherent evaluation in `L1011_ENGINEER_PANEL`. Every breaker row carries its number ("ENG START PWR, breaker 741: in") — titles repeat ("INOP" ×68) — and the window re-filters ONLY on opening, a search or "pulled only" change and Refresh, never after a pull, a push or its confirmation read (the Ctrl+M monitor managers' rule), so the cursor never lands on another breaker. A position variable that two rows share rides the batch ONCE; the second row reads it on request. → [l1011.md](../l1011.md)
