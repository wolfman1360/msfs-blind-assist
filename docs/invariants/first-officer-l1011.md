# First Officer: iniBuilds L-1011 TriStar — rules in full

Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/first-officer-l1011.md`, which Claude Code loads when it reads matching code. Background: [first-officer.md](../first-officer.md) (the TriStar paragraphs) and [l1011.md](../l1011.md) (First Officer).

## FOL-1

- The TriStar First Officer never writes a control in a way of its own. Every write goes through the definition's First Officer entry, reached through `IL1011FoTransport` (`L1011DefinitionFoTransport`): `IniL1011Definition.FoSetAsync` for a map row, a lever or the stabilizer trim, `FoSetAltimetersAsync` for the captain's, first officer's and standby altimeters in one string, and, for the pressurization panel, `FoSetCabinBaroAsync` for the cabin barometric setting and `FoSetCabinAltitudeSelectorAsync` for the cabin altitude selector ([FOL-5]). `FoSetAsync` plans a map row through the panels' own write core (`PlanFor`, `ApplyPlan`) and sends a lever or the stabilizer trim from the panels' `L1011Levers` table, so a flow step writes a control exactly as a panel pick does: the click replay ([L1011-1]), the refusal of a toggle from an unknown position ([L1011-4]) and the engage paddle's CWS notch ([L1011-21]) included. `FoSetAltimetersAsync` plans nothing: it sends `L1011Levers.AllAltimetersRpn`, Ctrl+B's string, directly, sharing that table's range check and the `CanLand` gate. Never `HandleUIVariableSet`, the panels' entry, which speaks its own refusals, snaps a combo back, runs only on the UI thread and does not wait for a held press; and never a raw calculator string from the executor. Unlike the panels, the entry speaks nothing. It returns `L1011FoResult`: Sent, AlreadyThere, Refused with the reason the panel would have spoken, Unavailable when the definition is detached or gone or the calculator path cannot land, or UnknownKey. It completes only once the plan has run, a button's hold included, and it marshals onto the UI thread captured at `Attach`, so the executor may call it from any thread. The executor (`L1011FoActionExecutor`) runs every write behind one gate. It reads a readable key fresh before writing it, so the definition plans from a delivered value and never from an empty cache, then reads it back fresh until it shows the target or `VerifyTimeoutMs` passes; only then is the write done. A press, a spring switch or a knob holds no position to read (`IniL1011Definition.FoCanReadBack`) and is done once sent. A write not done is logged with its reason and never spoken by the executor: the flow says "Skipping", and a hand tick unticks with "Unable to complete". → [first-officer.md](../first-officer.md)

## FOL-2

- One voice. MainForm's UI echo ([CORE-8], [CORE-9]) covers only a panel pick, so a lever the First Officer moves (the parking brake, the flap handle, the ground-spoiler arm) would otherwise be spoken twice: the flow's own line, then the aircraft's lever call-out ("Parking brake set"). So the First Officer's hand-written writes (`FoSendCustom`) record their target in the definition's commanded state (`_commanded`, an `L1011CommandedState`) before sending, and `AnnounceLever` stays silent for a lever that reads its commanded position within the commanded hold. Nothing is recorded for a write that cannot land. A lever moved by anything else (the pilot, a hardware lever, the aircraft) is still spoken; a panel pick is not recorded, because the UI echo already keeps it quiet. Every First Officer test that changes lamps mutes the warning-light call-outs with `FoMuteLampSpeech` for its whole run and re-arms the mute right before every phase, because on the 1 Hz batch every fresh read waits for the next batch and a test can outlast one window, and a lamp change that begins after the window is spoken: the standby power check for `StandbyCheckMuteMs` (20 s) from its start and again right before its step 3 writes and its step 4 light round; the engine and APU fire test and the wheel well fire test for `FireTestMuteMs` (45 s) before each phase; the hydraulic check, whose pumps change the brake accumulator lights, for `HydraulicCheckMuteMs` (60 s) before each phase. A test ended early re-arms it once more before it puts its switches back. A re-arm only ever moves the end later (`L1011LampGate.MuteUntil` keeps the later end); the mute's end is left to its time-out, never cut short, and a running annunciator light test is never shortened. Each test speaks ONE verdict of its own through the announcer ([FO-26]): a sentence naming the first light (for the hydraulic check, the first pressure) that read wrong, such as "Standby power check: AC standby bus fail light came on" or "Hydraulic check: system B pressure did not reach 2,000 psi", always; "Standby power check: pass" only while "Speak flow progress" is on. A write the test could not do is the flow's to say. A wrong light does not stop the check, so the aircraft still ends with the battery on and standby power armed, and a lamp test still ends with its test switches off ([FOL-7]). → [first-officer.md](../first-officer.md)

## FOL-3

- The TriStar's start cue is N3, so the First Officer reads its engines on N3 (`L1011_RO_N3_1` to `_3`, the engine gauges' `L:INI_ENGn_N3`), never the window's stock N2 feed: `L1011FoStateEvaluator` stores what `IFoEngine3N2Sink` delivers and no TriStar field reads it. An engine is running at N3 50 or above (idle is about 59). The engines are stopped when every N3 is below 15 (`EngineStoppedN3`) AND every fuel and ignition switch AND every ground start switch (`SWITCH_GND_START_ENG_n`) reads off. A cold N3 gauge reads 1.4 to 1.9, never 0, and an engine windmilling in a light tailwind read 5.05 with its fuel and start off, which the old threshold of 5 called turning, so every cold-and-dark guard refused. 15 sits well under the 20 % where a start puts fuel on, and the ground start switch keeps an engine being motored from ever reading stopped. The fuel and ignition switches are read on their rows (`TOGGLE_CUTOFF_ENG_n`, which read the stock fuel valves), never the L:var of that name, which reads 1 on a cold aircraft. An unread input is NaN, so the cold-and-dark guards (`FO_ENGINES_STOPPED`, [FO-25]) stop the flow rather than let it through. → [first-officer.md](../first-officer.md)

## FOL-4

- The engine start is the one TriStar step a stopped flow must not leave half done, so a ground start's release has a single owner, the MD-11's START switch shape. A flow step's ground start (`FO_GROUND_START_n`, `GroundStartAsync`) records the start with the run's Stop in `_flowGroundStarts` BEFORE the switch's click goes out, so a click that lands late, or never reads back, is still one to release; a checklist tick's start, the pilot's own and a switch found already on are never recorded. The record is forgotten once that engine's fuel and ignition write is done: the start then runs on, and the aircraft releases the switch itself past about 55 % N3. Whoever takes the record out releases the start, once. After the flow's Stop that is `OnFlowStoppedAsync` (the run's Stop clean-up, which FlowManager runs once the step has returned; it releases under the gate) or `ReleaseHeldPresses` (the window's close, on the UI thread while the aircraft still takes writes; it releases over the cached fuel and switch readings, `ShouldReleaseGroundStart`, not awaited and not read back), whichever comes first. The stopped watch itself (the rotation watch, or the light-off watch `FO_ENGINE_LIGHT_OFF_n`) never releases its own run's start after a Stop: it resumes from the cancel on another thread, so it could beat the window's close to the record and then find the First Officer detached, or the aircraft gone, before its click. A watch that timed out, or a click not done, takes the record under the gate and releases it there (`GiveUpGroundStartAsync`). The release reads the engine's fuel and ignition first, on the row that reads the stock fuel valve (`TOGGLE_CUTOFF_ENG_n`, [FOL-3]): unread, the switch is left as it is; on, the start runs on; off, the switch is read, and while it reads on it is released by the row's own click to 0 (`L:SWITCH_GND_START_ENG_n` 0 with its `H:STARTER` events), which releases the starter: with an engine turning on APU air and its fuel off, the starter and the switch read 0 at once and N3 fell away. The switch is never clicked from an unread position, since its click carries the same `H:STARTER` events either way. The release never writes a fuel switch and never cuts fuel, and the executor speaks none of it. A flow's start that could not be released (its fuel and ignition unread, its switch unread, or its click to 0 not done or not reading off), by `OnFlowStoppedAsync`, by `ReleaseHeldPresses` or by a flow step's give-up, may still turn a dry engine on APU air, which a blind pilot cannot see; so it joins the stopped run's notice, "Engine 2 ground start switch still on: release it.", one sentence per engine, joined by a space. `TakeStoppedRunNotice` hands it over once and clears it, and FlowManager queues it right after the run's own end sentence ("flow stopped. Unable to complete: …" or "flow cancelled"), whatever "Speak flow progress" says ([FO-26]: a failure always speaks). Spoken by the executor before that sentence, the interrupting "flow stopped" cut it off. A clean release, a switch already off, a start whose fuel and ignition are on, an unreachable or detached First Officer and a hand tick's give-up (no run to end) add nothing. → [first-officer.md](../first-officer.md)

## FOL-5

- The cabin altitude selector is a knob whose own state variable, `L:FLT_CAB`, holds its step (0 to 100); the aircraft's gauge computes the cabin altitude the step commands (`L:TARGET_CABIN_ALTITUDE`) when the knob's own H: event arrives. So the First Officer turns it the way the knob's click does ([L1011-1]): `IniL1011Definition.FoSetCabinAltitudeSelectorAsync` seeds ONLY `L:FLT_CAB`, one step past the target, then sends ONE `H:ROTARY_FLT_CAB_DEC`, the control map's own dec event, and the gauge steps the knob onto the target; the top step (100) is seeded one below and clicked up with `H:ROTARY_FLT_CAB_INC`. Both go in one string, sent quietly through the same `CanLand` gate as the definition's other hand-written writes; a step outside 0 to 100 is refused and nothing is sent. Never more than one click in the string: several H: events in one string moved the knob one step. Never a write of the target cabin altitude itself: the aircraft computes it from the step. The executor (`CabinAltitudeSelectAsync`, `FO_CABIN_ALT_SELECT`) turns a target in feet into the knob step with `L1011Pressurization.KnobStep` (clamped to the knob's travel), then reads `L1011_RO_CABIN_ALT_SELECTED` back fresh until it is within `CabinAltitudeToleranceFt` (150 ft) of the target. That readout is written in feet but delivered in metres, so every comparison converts it (`MetresPerFoot`), the executor's read-back and the evaluator's `FO_CABIN_ALT_AT_CRUISE` and `FO_CABIN_ALT_AT_DEST` alike. Preflight's target is the cabin altitude that holds the maximum differential at the plan's cruise (`CruiseCabinAltitudeFt`), Descent's the plan's destination elevation clamped to the selector's end stops (-250 to 8,000 ft); without a plan nothing is sent or spoken and a Captain step asks ([FO-20]). → [first-officer.md](../first-officer.md)

## FOL-6

- The tank 2 left fuel pump (`SWITCH_FUEL_PUMP_2L_1`) feeds the APU from the moment it starts turning, not only once it is up to speed (about 50 s after the start press). So a TriStar fuel pump cut, Power Up's "Fuel pumps: all off" and Shutdown's, is left alone while `FO_APU_STARTING_OR_RUNNING` reads on (APU RPM at or above `ApuStartingRpm`, 1 %), never only while `FO_APU_RUNNING` (95 %) does: an APU still spooling up feeds from the same pump. The guard is on the flow step (`LeaveAloneWhen`, spoken "Fuel pumps left on: the APU is running.") and on its hand tick (beside the parked guard, [FO-25], spoken with the tick's left-alone sentence, which names the APU), and the step's lines stay out of the latch. An unread APU speed does not hold the cut back: the cut already sits behind the read-only ground and engines-stopped guards, which fail unread. Shutdown's APU wait agrees with the guard: it waits up to 150 s for the RPM to read below the same 1 % (`SD_APU_STOPPED`, read only), "Already set" when it already does and run otherwise, unread included, whether or not this run sent the stop, so an APU found coasting between 1 and 5 % (stopped to the stop step) is waited out before the master and the pump cut, and the pumps come off once the APU is still. Parking never cuts the APU's feed: its fuel panel step (`PK_FUEL_PANEL`) turns the tank 2 left pump on first, then the other seven pumps off, the engine 2 tank valve on under its closed guard and the crossfeeds closed. It runs only after two read-only Stop waits: `FO_POWER_SOURCE_ON` (the APU generator or external power on line before the fuel and ignition go off, so the buses never drop to the battery, the MD-11's `PK_POWER_SOURCE`) and then `FO_ENGINES_STOPPED` (`PK_SPOOL_DOWN`, directly after the fuel cut and before every other write: no tank pump off under a turning engine, and the anti-collision lights, the ground crew's sign that engines turn, off only once they stop, as the MD-11's beacon). Parking's fuel and ignition tick holds to the same order on its own: it is left alone unless the aircraft reads on the ground with `FO_POWER_SOURCE_ON` on ("Fuel and ignition left on: not on the ground, or no APU generator or external power on line."), unread refusing. → [first-officer.md](../first-officer.md)

## FOL-7

- The TriStar First Officer runs only the tests whose result BA can read, each speaking one verdict ([FOL-2]). The standby power check (Power Up, `StandbyPowerCheckAsync`) reads the standby and essential bus lights. The engine and APU fire test (`FO_FIRE_TEST`, `FireTestAsync`) turns both loop test switches off, sets the four loop selectors to Both and leaves them there (the single-loop positions do not match their labels), then switches tests A and B on TOGETHER and reads the three engine fire lights, the engine fire warning and the APU fire light lit, then both off and the five out. On APU and external power with the engines off, test A alone lit nothing (held 8 s), while B alone, and A with B, lit all five: a test of A on its own would name five lights that cannot come on. The fire detection loop light never lit and is not read. The wheel well fire test (`FO_WHEEL_WELL_FIRE_TEST`, `WheelWellFireTestAsync`) sets its loop selector to Both and switches A and B on together (A alone lit nothing), reading the engineer panel's wheel well fire light; the main panel's stayed out and is not read. The hydraulic check (`FO_HYDRAULIC_CHECK`, `HydraulicCheckAsync`) is the manual's: system B's AC pump, then C's, then both power transfer units, each system's pressure read up, then everything off and every system read back down. The turbine overheat and area overheat tests are never run, mentioned in no flow and listed in no read-back: their lights never lit, so a pass could not be told from a failure. Each test is an atomic composite that keeps the dispatch gate for its whole run (a hand tick moving a test switch or a pump mid-test would corrupt it), every wait bounded on the transport's clock. It re-arms the lamp mute before every phase ([FOL-2]); a wrong light or pressure does not stop the phases, so the test switches still end off and the pumps and power transfer units off; a write not done (or a throw) ends the test at once with those put back, each tried. One verdict: the first wrong light or pressure always, "Engine and APU fire test: pass" and the like only with flow progress on. A failed test never stops its flow: its step's policy is Skip, and its lines stay out of the latch. Two more of the same kind, each pinned by the flow tests: the drain mast heaters are in no flow and no checklist, because on the ground the aircraft puts both switches back to off within about 4 s, by hand too, so a step could never read done; and the doors check (Before Start, `FO_DOORS_CLOSED`) reads the four exits' stock positions (`EXIT OPEN:0` to `:3`, `DoorPositionKey`), each closed below 5 %, never the main panel's door light, which does not follow the doors (it stayed out with the main door open). → [first-officer.md](../first-officer.md)

## FOL-8

- The TriStar's APU takes about half a minute to a minute to stop after its stop press, longer than a checklist tick's 10 s grace ([FO-11]). So the APU stop (`FO_APU_STOP`, `ApuStopAsync`) is a Stop-aware composite in the APU start's shape. One write phase under the gate, never begun after the flow's Stop: the RPM read fresh (unread, not done and nothing pressed; below `ApuStoppedRpm`, 5 %, done with no press); a stop press this executor sent on the same transport still inside its spin-down is waited for, never pressed again; otherwise one press of the stop button (`APU_STOP`), recorded on the transport's clock. Then, the gate released, a read-only wait until the RPM reads below 5 %, up to `ApuSpinDownWaitMs` (90 s): a flow's Pause holds it and its Stop ends it. Holding until the APU reads stopped is what keeps a hand tick's line, judged on `FO_APU_OFF`, from reverting while the APU runs down; a press counted done once sent would revert it. The flows' APU master off (After Start's and Shutdown's) requires the stop step (`Requires`): a stop skipped, by After Start's engine generators wait or because the APU never read stopped, leaves the master on, saying "APU master left on: the APU did not stop."; an "Already set" stop counts as done. The master's hand tick, which has no flow behind it, is left alone with the same sentence unless `FO_APU_OFF` reads on (`ApuNotStopped`), unread refusing. Before the master goes off, After Start waits the manual's two-minute cool-down after a stop the run sent, and Shutdown waits up to 150 s for a standstill below 1 % whoever stopped the APU ([FOL-6]). Shutdown's battery follows the master: its step requires the master step ("Battery left on: the APU did not stop."), and the step and its tick are both left alone while `FO_APU_STARTING_OR_RUNNING` reads on, because a master found off over an APU still turning is "Already set", not skipped, so the dependency alone would let the battery go; an unread APU speed does not hold the step back, the flow's guards having read the aircraft parked. → [first-officer.md](../first-officer.md)

## FOL-9

- A TriStar flow or hand tick run in the wrong phase of flight is guarded, and an unread on-ground flag fails the guard. After Landing turns the air data heat and anti-skid off, zeroes the stabilizer trim and stows the speed brake lever: started in the air by mistake it would hurt the landing, so it opens with `OnGroundGuard("AL_ON_GROUND")` (read only, Stop, links no line), as the shutdown and securing flows do. A hand tick has no flow guard of its own, so the After Landing anti-skid, air data heat, stabilizer trim, speed brake and flaps ticks are each left alone off the ground (`NotOnGround`), aloud, each with its own sentence ("Anti-skid left on: not read on the ground.", and the like). After Takeoff's gear step and its tick move the lever up only with the aircraft read airborne: on the ground, or with `SIM_ON_GROUND` unread, both are left alone (`NotAirborne`, "Gear left down: on the ground."). The gear lever's gauge script refuses gear up on the ground; no live check has seen it, so nothing relies on it; the gear-up check that ends the flow is unchanged ([FO-13]). → [first-officer.md](../first-officer.md)
