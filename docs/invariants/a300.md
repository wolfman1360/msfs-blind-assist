# iniBuilds A300-600 — rules in full

Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/a300.md`, which Claude Code loads when it reads matching code. Background: [a300.md](../a300.md).
The text is verbatim from CLAUDE.md on `feat/inibuilds-a300` as of `8f6ad85e`, moved here when that branch took the lean CLAUDE.md (#265); a trailing "→ doc" pointer is the original's.

## A300-1

- A map-driven A300 row is written by firing the control's OWN B: event, `value (>B:AIRLINER_<Name>_Set)`, through `ExecuteCalculatorCodeUnique` (`A300WritePlan`) — never `SetLVar` and never a bare L:var write. A TWO-POSITION switch's Set event FLIPS it whatever value it is given (iniBuilds' own `_ON`/`_OFF` bindings flip too, measured 2026-10-03), so a toggle or command row is sent only when its current position is KNOWN and differs, refused aloud ("position unknown, try again in a moment") otherwise, and a just-commanded position is trusted for 2.5 s over the 1 Hz cache (`A300CommandedState`); a flip sent the wrong way inverts the switch. Selectors and knobs are absolute; hold buttons are Set 2, 250 ms, Set 0, except the six fire tests, held as long as the aircraft's own checklist holds them (`A300WritePlan.TestHoldMs`: loop tests 5 s, squib tests 3 s; 250 ms never finished one, measured 2026-10-04), and the takeoff config, landing gear warning and smoke tests, held 5 s (a 250 ms takeoff config press reported nothing even in landing configuration); spring switches are held 1 s and returned to rest. The flaps lever, ground spoiler arm and speed brake are the hand-written exception (`A300Levers`: `K:FLAPS_SET` index x 4096, `K:SPOILERS_ARM_SET` read back from `L:INI_SPOILERS_ARMED` because the stock armed flag stays 0, `K:SPOILERS_SET`). Every write is refused aloud ("{name} unavailable") when `CalcWriteCanLand` is false and the row is asked for again so its combo snaps back. → [a300.md](../a300.md)

## A300-2

- `MSFSBlindAssist/Resources/a300_control_map.json` is GENERATED by `tools/a300-gen` from the aircraft's compiled cockpit behaviour and tooltips — never hand-edit it; regenerate after an iniBuilds update and review with `diff_maps.py`. iniBuilds' files and any decoded copy of them stay out of the repo. → [a300.md](../a300.md)

## A300-3

- `A300PanelLayout` is the ONLY source of A300 panel order: WHICH panel a control is on follows iniBuilds' own component tree (so an update is picked up by regenerating), while the ORDER is `A300PanelLayout.Order.cs` (owner decision, 2026-10-04): `PanelOrder` uses the app-wide convention, Electrical first on the overhead as on every other aircraft, and `LeadRows` opens six panels on what the A300 checklist reaches first; everything else keeps cockpit-file order, and a panel or row the lists miss stays after the listed ones, never dropped. It also splits the pedestal's "STD" radio and audio group by what each control is, names every unclear or clashing control in `A300PanelLayout.Names.cs` (iniBuilds' titles repeat, and two are wrong: "ALTITUDE KNOB" on the V/S knob, "CPT BAROMETER" on the first officer's), and puts a guard directly before its switch. Guard COVERS are never rows (they only move the model); the two cargo smoke agent guards are real switches the agent switch depends on. → [a300.md](../a300.md)

## A300-4

- The A300 MCDU screens come from the client data areas `iniAirbusMCDU_1`/`_2` (1008 bytes), published only while `L:INI_MCDU_OPTION` is 1 — which does NOT survive a flight load, so the MCDU window writes it on EVERY open. `A300McduDataManager` keeps the MD-11 manager's rules: one per connection (reused, never re-registered, on the same handle), ON_SET + CHANGED subscription PLUS a one-time snapshot on a DIFFERENT request id. Read characters through `A300McduText.Glyph` — the MCDU fonts draw `!` as an entry box, `^` as a degree sign and `a`/`b`/`l`/`r`/`{`/`}`/`~` as arrows and a delta (decoded from the glyph outlines), never as the letters they are. MCDU keys are `INI_MCDU1_`/`INI_MCDU2_` L:var pulses through the definition's ONE queue: a press and release in ONE calculator string does not register. Never press CLR on an empty scratchpad (the A300 puts "CLR" into it); the clear-all re-reads after each press. → [a300.md](../a300.md)

## A300-5

- A300 typed values go through `A300TypedValues` only. NAV frequencies are written as their `_MHZ`/`_KHZ` L:var parts (the combined `INI_VOR1_FREQUENCY` and the stock NAV radio are rebuilt from them, so writing either is silently undone). A typed speed in the other unit sends SPD/MACH, WAITS `ModeSwitchSettleMs`, then writes — never in one string: the aircraft applies the switch later and converts whatever the variable holds then. Altimeters are `index value (>K:2:KOHLSMAN_SET)`, index FIRST. → [a300.md](../a300.md)

## A300-6

- The A300 tablet reader (`coherent-a300-efb-agent.js`) presses with ONE click event (pointer and mouse down/up, then click; a bare `el.click()` is ignored and two clicks would run a toggle twice), never requires a non-zero size on a CONTAINER (the page container is 2048 x 0), never `focus()`es a field (the on-screen keyboard covers the page), and never reads a password field's value. The press goes where a finger on the control's centre would land (`A.pressTarget`: the topmost element there when it is inside the control, else the first inner element with its own onclick), NEVER on the stamped control alone: the tablet hangs the Unlock and gear handlers on the picture INSIDE the button, so a press on the button did nothing and the tablet could not be unlocked (2026-10-04). An overlay (control box, its confirmation, powered off, pause, My Flight's viewers) is read ALONE under its own page name, and found with `A.shown` (every ancestor displayed), never `A.visible`, which looks at one element and lets a hidden page's viewer pass. → [a300.md](../a300.md)

## A300-7

- The master warning and master caution speak only as they come ON: pressing the light writes 0 to the same `INI_MASTER_*_ACTIVE` variable, so speaking it going out would announce the pilot's own press. Lamps and the four announced levers speak from `ProcessSimVarUpdate` inside MainForm's mute and echo wrap (`DefAnnounceMuteSets` lists `INI_A300`); a context reset wipes the baselines and `Md11SeedGate` decides when the unchanged ones are seeded from the cache. → [a300.md](../a300.md)

## A300-8

- The A300 display readers read ONLY aircraft variables and stock SimVars: never the simulator's memory, a picture or AI (the owner's rule, 2026-10-04). So the upper ECAM's memos and warnings and the ND's waypoint name and bearing are NOT read: they live inside the aircraft's display software, not in any variable. Do not "complete" them with a memory read or an AI capture without asking the owner again. → [a300.md](../a300.md)

## A300-9

- The FMA (`A300Fma`) transcribes the A300's own PFD::drawFMA (v1.0.11) word table, characterised by running that routine on chosen mode numbers; change a word only from a new characterisation, never by analogy with the A320. It is composed once a sample at the end of the batch that carries its sources (`DeferredFlushWatchVariable` = the pitch mode key, all 27 sources in ONE batch, pinned by `IniA300FmaBehaviourTests`; the batch boundary is at the 300th name in ordinal order, so ANY new batch-covered A300 variable can push the last sources, `INI_pitch_trim1/2`, into batch 2 — the 58 fault lights did, which is why they have their own subscriptions), and spoken there, OUTSIDE MainForm's mute wrap, so it checks `A300DisabledMonitorVariables` itself (`IsMuted`). Six sources are shared rows and lights (the autothrottle and SPD/MACH lights, both A/THR master switches, both autopilot switches, both pitch trim switches) and must never be registered a second time. The thrust column is blanked together with the guidance columns while the PFD would draw none (an IRS aligned, essential bus 2 powered, pitch trim 2 or pitch trim 1 with the captain's FD source): a DELIBERATE divergence, because the mode numbers keep old values cold and dark. Baseline-first; the guidance columns appearing and a settling flight load (`Md11SeedGate` armed) are silent. → [a300.md](../a300.md)

## A300-10

- The A300 display boxes read: green dot, S and F only at the flap lever positions the speed tape draws them (0; 1; 2 and 3 — `PFD::drawSpeedTape`); VMAX is `INI_max_speed` (the tape's top, 270 with the gear down), not `INI_VMAX_SPEED` (VMO); the standby altimeter is `INDICATED ALTITUDE:3` (it follows baro 3, measured); the ILS receiver is NAV 3; the fuel tank weights are KILOGRAMS (they sum to the stock total) and fuel reads in the tablet's unit (`L:INI_IS_METRIC`). An ECAM page lists only what its own drawing routine PRINTS as a number; a needle with no printed number or a value whose unit the page does not establish is left out, never guessed. → [a300.md](../a300.md)

## A300-11

- The A300 take-off call-outs (`A300TakeoffCallouts`) take V1 and VR from `L:INI_V1_FMGS`/`L:INI_VR_FMGS` (the MCDU take-off page) and V2 from `L:INI_V2_FMGS`, which FOLLOWS THE FCU SPEED WINDOW (250 with V2 typed as 150, measured 2026-10-04), because the A300 crew sets V2 on the FCU for take-off. So V2 is used only when `PlausibleV2` accepts it: at or above VR and at most 30 knots above. Never read `INI_V2_FMGS` as the MCDU's V2, and never announce its changes (every FCU speed change moves it). The arm is dropped on every context reset AND reconnect, never the speeds (the shared machine's rule). → [a300.md](../a300.md)

## A300-12

- The A300 fault lights (`A300FaultLights`, 58) stream on their OWN once-a-second subscriptions (`ExcludeFromBatch`), never the continuous batch, to keep the FMA's sources in one batch. Each change is collected in `ProcessSimVarUpdate` only when `announcer.Suppressed` is false THERE (MainForm's mute and echo wrap) and spoken at the next continuous batch end as ONE sentence (`A300LampCallouts`), so a muted light must never be collected and spoken later outside the wrap. Names come from mapping the cockpit model's emissive nodes to the light variables; never name a light from its variable alone (`INI_ENGINE1_BLEED_LIGHT` lights a wing anti-ice node and is left out for that reason). → [a300.md](../a300.md)

## A300-13

- A300 autopilot and autothrottle engagement call-outs (`A300EngagementTracker`) are silent for the pilot's own MSFSBA pick, judged by `A300CommandedState` (the row or hotkey recorded the commanded position within 2.5 s); never by a value compare against the cache alone, which cannot tell a yoke button from the panel. Their Ctrl+M rows ride `INI_AUTOPILOT_DISCONNECT` and `INI_AUTOTHROTTLE_DISCONNECTED`, registered only to carry the rows; nothing reads their values, which were never measured. → [a300.md](../a300.md)

## A300-14

- Of the A300 FCU windows, ONLY the altitude window is announced on its own (`A300FcuWindows`): `INI_Altitude_Dial` is written by the knob handlers alone, while the aircraft's own autopilot logic also writes the heading, speed and vertical speed windows (heading sync, managed speed, `SyncVerticalSpeed`), so announcing those would speak changes nobody made. A panel knob step on any of the four is read back once it lands; MSFSBA's own typed altitude or altitude step suppresses the altitude call-out for 2.5 s. → [a300.md](../a300.md)

## A300-15

- The A300 decision height is `L:INI_MINIMUMS_PILOT` (and `_FO`): the stored value, written directly by the typed Decision height box. The DH knob changes it only while `L:INI_DH_SELECTED` is 1 and steps the flight path angle otherwise, so a knob-based setter would silently move the FPA instead. → [a300.md](../a300.md)

## A300-16

- Measured live 2026-10-05 at the gate (external power and batteries on, package 1.0.11, through the Coherent debugger on VCockpit01 with the same B: events the app fires). Pulling the captain's or first officer's altimeter knob is STD and pushing is QNH, as iniBuilds' tooltips say ("SET STD PRESSURE", "SET QNH PRESSURE"); the push event writes a variable named `INI_<side>_ALTIMETER_STD_COMMAND`, so never trust the name. `L:XMLVAR_Baro1_Mode` / `Baro2_Mode` read 1 in STD and 0 in QNH and drive the altimeter's STD flag; the standby (Baro3) has no push or pull. A pull saves the setting × 16 in `L:INI_BARO1_PRESSURE` / `INI_BARO2_PRESSURE`. But STD is a FLAG ONLY: the Kohlsman setting does not change, the drums keep reading against it (500 feet at 1024.94 in STD against a pressure altitude of 197), the knob still turns in STD, a push does not restore the saved value, and `A:KOHLSMAN SETTING STD` stays 0. So Ctrl+B's STD pulls only the sides in QNH (pulling a side already in STD would save 1013 over its QNH) and then writes 1013.25 to all three altimeters; QNH pushes the sides in STD and restores each one's saved setting, the standby taking the captain's. A side already in QNH is never restored (what it saved may be older than what it shows), and a saved setting outside 955 to 1060 hectopascals is reported, never used. Each press is confirmed by reading the mode back before anything is written. The mode variables stream on their own subscriptions, never the batch ([A300-9]). → [a300.md](../a300.md)

## A300-17

- `BaseAircraftDefinition.ShowTrackedWindow` keys its registry on the window's TYPE, and all five A300 value boxes (Ctrl+S, H, A, V, B) are `ValueInputForm`, which stays open after Set. Without a check, a second hotkey found the open box under the same type and re-showed it: with the speed box open, Ctrl+H brought back the speed box. `ShowValueDialog` therefore closes an open box whose title differs before asking for the new one (`A300AutoflightWindows.ReplacesOpenBox`); closing removes it from the registry, so the factory builds the requested box. → [a300.md](../a300.md)

## A300-18

- The input-mode windows name a control exactly as its panel row does (`A300PanelLayout`), so one control has one name across the app, and add what a knob push or pull does in iniBuilds' own tooltip words, which the generator copies into the map's `action` field ("Heading knob push, aircraft heading"). Words that only repeat the name are dropped ("SET SPEED KNOB" on the speed knob pull). Each control sits in one window only: the value boxes carry their axis's knob push and pull and mode buttons, and Ctrl+P carries the engage cluster, the approach modes (VOR LOC, Land), the disconnects, TOGA, the bank limit and the flight directors, as on the PMDG. Every press goes through the panel row's write path, so the refusals ("unavailable", "position unknown") and the commanded-state hold match the panels. In the value boxes a lamp button is read back fresh and a knob push or pull says nothing; Ctrl+P says nothing on a press. → [a300.md](../a300.md)

## A300-19

- The tablet's IDC option (Settings, `opt_idc1/2`, `L:INI_IS_IDC`) puts the IDC on the pedestal in place of the classic radio panel, and then the IDC owns the transponder mode: `IDC::Update` (1.0.11, read from the module) writes `L:INI_tcas_mode_pedestal` from its own ATC page every frame while the option is 1. Measured on the KSFO ground probe (2026-10-04): with the option at 1, `2 (>B:AIRLINER_TCAS_MODE_Set)` showed TA/RA in MSFSBA's combo while the aircraft put the mode back to standby, and a direct write reverted too; with the option at 0 the mode held. MSFSBA does not drive the IDC, so while the option reads 1 the pedestal transponder mode row is refused aloud ("Transponder mode: set from the IDC") and re-read so its combo goes back to the mode the aircraft reports (`A300Idc.Refuses`); it never writes. An option not read yet refuses nothing. The option streams on its own once-a-second subscription, consumed silently, never the batch ([A300-9]). → [a300.md](../a300.md)
